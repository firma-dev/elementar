# бриф · финансер

Первый выпускаемый корпус Элементара. Читать вместе с `elementar-canon.md` и `CLAUDE.md`.

---

## Что это

Браузерное приложение для личных денег. Открывается по ссылке, работает без сети, данные не покидают устройство. Считает арифметика, не модель.

**Первый пользователь:** автор. Второй круг: друзья и родственники по ссылке.

**Цель первого выпуска:** живой продукт на домене, которым пользуется хотя бы три человека кроме автора. Не полнота функций.

---

## Главное архитектурное правило

**Цифры считает код. Модель только формулирует.**

Модель никогда не получает задачу «посчитай». Она получает готовый результат и превращает его в человеческую фразу. Если в её ответе появилось число, которого не было во входе — ответ не показывается.

Приложение обязано полностью работать при недоступной модели. Модель — надстройка, не зависимость.

---

## Модель данных

Единственное решение, которое дорого менять потом. Определить первым, до всего остального.

```ts
type Transaction = {
  id: string;          // стабильный, из хеша полей — для дедупликации
  date: string;        // ISO, YYYY-MM-DD
  amount: number;      // всегда положительное, в минорных единицах (копейках)
  direction: 'in' | 'out';
  currency: string;    // ISO 4217
  category: string | null;
  payee: string | null;
  account: string;
  source: 'manual' | 'import';
  raw?: string;        // исходная строка импорта, для отладки
};
```

Суммы — целые числа в копейках. Никаких float для денег.

Дедупликация по `id` при повторном импорте того же файла обязательна — это первое, на чём такие приложения ломаются.

## Что входит в первый выпуск

**Ввод данных**
- Ручное добавление операции — работает всегда, это основной путь
- Распознавание скриншотов банковского приложения (см. отдельный раздел ниже)
- Дедупликация при повторном добавлении

**Категории**
- Словарь правил: подстрока в `payee` → категория
- Поправка пользователя запоминается и применяется дальше
- Никакой модели: правила пользователя точнее любой генерации

**Экраны**
- Список операций с фильтрами: период, категория, направление
- Сводка: сумма по категориям за период, сравнение с предыдущим
- График: траты по дням и по категориям

**Хранилище**
- IndexedDB на устройстве
- Экспорт в JSON — обязательная функция, не опциональная. Хранилище браузера теряется
- Импорт этого JSON обратно
- Предложение выгрузить бэкап раз в неделю

**Раздача**
- Статика на домене, путь `/финансер`
- Никаких аккаунтов. Данные локальные, ссылка одна и та же для всех

## Распознавание скриншотов

Главная функция ввода. Причина: выписку в CSV банки прячут, а скриншот делает любой человек с любым банком.

**Поток строго двухшаговый.**

1. Пользователь добавляет один или несколько скриншотов. Перед первой отправкой — экран согласия честным текстом: изображение уходит на распознавание внешнему сервису, вот что именно уходит.
2. Возвращается таблица распознанных строк: дата, сумма, получатель. Все поля редактируемые. Пользователь проверяет глазами и подтверждает. Только после подтверждения данные попадают в хранилище.

**Автоматическая запись запрещена.** Правило канона: предлагает, но не делает. Именно это делает ошибки распознавания безвредными.

**Обрезка перед отправкой.** Приложение предлагает обрезать изображение до списка операций, отсекая шапку с балансом. Обрезка выполняется на клиенте, до любой отправки.

**Реализация.** Зрительная модель через прокси-Worker. Worker ничего не сохраняет: ни изображение, ни ответ, ни в логи, ни в базу. Модель возвращает строго JSON по схеме; невалидный ответ не применяется.

**Деградация.** Нет сети, кончился лимит, отказ от согласия — ручной ввод работает как обычно. Приложение не должно становиться бесполезным без распознавания.

Любой пункт отсюда, попавший в первый выпуск, срывает срок.

## Дизайн

**Токены — отдельный файл, единственный источник правды.** Оба существующих прототипа пересобираются на нём. Хардкод цветов и отступов — ошибка.

Эталон — интерактивная модель бизнес-плана. Что переносится:
- плотная сетка карточек, минимум воздуха
- крупная цифра, мелкая вторичная подпись
- ползунок как основной элемент управления вместо поля ввода
- мгновенный пересчёт без кнопки «применить»

Типографика: текст — Basis Grotesque Pro. Все цифры и единицы — OCR A Becker RUS-LAT, без исключений.
Тени жёсткие, без размытия. Вёрстка компактная.

## Порядок работ

1. Токены дизайн-системы отдельным файлом
2. Типы и модель данных
3. Хранилище: запись, чтение, экспорт, импорт
4. Ручной ввод операции
5. Список с фильтрами
6. Расчёты как чистые функции: массив на вход, числа на выход
7. Сводка и график на этих функциях
8. Словарь категорий с запоминанием поправок
9. Сборка, деплой на домен — на этом продукт уже живой
10. Прокси-Worker для зрительной модели, без сохранения
11. Экран согласия и обрезка изображения на клиенте
12. Распознавание: скриншот → таблица с правкой → подтверждение → запись

Пункты 6–7 — там, где раньше работал чат. Каждая функция чистая: без обращений к хранилищу и сети, только вход и выход.

## Готовность

Первый выпуск считается готовым, когда:

- автор ведёт в нём свои деньги неделю и не возвращается в старый прототип
- приложение открывается по ссылке на телефоне и работает без сети
- экспорт и импорт JSON проверены на реальных данных
- трое людей получили ссылку и открыли её
