# Элементар

Монорепо набора узких браузерных приложений («корпусов»).

## Читать перед работой
- `elementar-canon.md` — рамка, принципы, набор корпусов. Не оспаривается.
- `ARCHITECTURE.md` — контракты между модулями. Меняет только агент `architect`.
- `DECISIONS.md` — журнал решений с датами. Дописывается, не переписывается.

## Стек
TypeScript, pnpm-монорепо. Клиент — Vite + Preact. Бэкенд — Cloudflare Workers + D1 + Durable Objects + R2. Домен и статика там же.

## Запреты
- Нет аккаунтов и авторизации. Доступ — по уникальной ссылке, раздача через QR, данные шифруются на клиенте.
- Файлы пользователя не уезжают на сервер. Обработка локальная.
- Нет магазина приложений. Каждый корпус — браузерное приложение, открывается по ссылке.
- Агент предлагает, но не делает. Всё, что создаёт агент, остаётся черновиком до подтверждения человеком. Это правило не имеет исключений.
- Никаких цветов и отступов хардкодом. Только токены.
- Зависимость не добавляется без решения архитектора.

## Владение файлами
Один файл — один владелец. Агент не правит то, чего ему не поручали; замеченную чужую ошибку называет в отчёте.

- `ARCHITECTURE.md` → architect
- токены и компоненты дизайн-системы → designer
- код корпусов и ядра → implementer

## Порядок работы
```
architect (контракт) → implementer (код) → reviewer (враждебное ревью) → implementer (правки)
```
Параллельно — только независимые участки. Один модуль двумя агентами одновременно не пишется.

## Именование продуктов
Предмет + «-ер», всё строчными, без английских слов: планер, финансер, конвертор, корректор, архивер, связной, постер, почтер, одинэсер.

## Порядок сборки
оболочка → двери → слои → мосты → связной последним.
Связной не начинать, пока не работают минимум три двери.
