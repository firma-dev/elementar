# Элементар

Оболочка для набора узких браузерных приложений и первая дверь — **планер**.

Данные живут на устройстве, шифруются на клиенте, сервер хранит слепые блобы и ничего о
них не знает. Аккаунтов нет: доступ к документу даёт ссылка, ключ едет во фрагменте URL
и на сервер не уходит никогда.

Полное техническое описание — [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).
Там же (§14.4) список решений, которые остались за владельцем.

## Что уже работает

- Планер: четыре списка, проекты, календарь, корзина, разбор дат из строки
  («продлить страховку завтра»), мобильный и десктопный виды, тёмная тема.
- Локальное хранилище на IndexedDB, документ переживает перезагрузку и работает офлайн.
- Криптография: дерево ключей, конверт EL1, подпись на каждый запрос, пароль как второй
  фактор поверх ссылки, одноразовые приглашения, файл-ключ для восстановления.
- Слияние правок для парного режима: свой оп-лог, гибридные логические часы, дробный
  индекс порядка, чистка надгробий по водяному знаку, хеш-цепочка для детекции форка.
- Бэкэнд на Cloudflare Workers: D1, три Durable Object'а, R2, WebSocket с хибернацией,
  два бакета лимитера, единый 404 без оракула перебора.
- Слот под модель: адаптеры провайдеров, предложения агента как наложение —
  агент предлагает, человек подтверждает.
- PWA: один манифест, сервис-воркер с проверкой хешей ассетов, обновление по кнопке.

754 теста, включая property-тесты слияния и тесты слепоты сервера.

## Быстрый старт

```bash
pnpm install
pnpm dev          # планер на http://localhost:5173
pnpm dev:api      # бэкэнд локально (wrangler)
pnpm check        # типы + тесты
```

Планер полностью работает без бэкэнда — он нужен только для синхронизации между
устройствами и парного режима.

## Раскладка

```
packages/proto     общий код клиента и сервера: константы, кодек кадров, канонизация подписи
packages/core      исполняемая среда документа: модель, слияние, крипта, хранилище, синк
packages/ui        дизайн-система, не знает слов «документ» и «docId»
packages/shell     оболочка: AppShell, шаринг, слот модели, панель агента
packages/llm       адаптеры провайдеров модели
packages/devkit    vite-пресет и шаблон сервис-воркера
apps/web           единое приложение: прихожая и все двери маршрутами
apps/api           Cloudflare Worker
```

Граф зависимостей проверяется скриптом:

```bash
node --experimental-strip-types scripts/check-deps.ts
```

Главное правило: `apps/api` не импортирует `@elementar/core` — иначе однажды кто-нибудь
попробует расшифровать документ на сервере.

## Прежде чем выкатывать

1. **Домен.** В `packages/proto/src/env.ts` три заглушки. Всё остальное — CSP, CORS,
   ссылки, QR — берёт значения оттуда. Нужен короткий ASCII-домен; кириллический годится
   только как редирект.
2. **Ресурсы Cloudflare.** `wrangler d1 create`, `wrangler r2 bucket create`, затем
   подставить `database_id` в `apps/api/wrangler.toml` (сейчас там заглушка) и выполнить
   `pnpm --filter @elementar/api migrate:remote`.
3. **Секреты.** `wrangler secret put ELM_IP_PEPPER` (32 байта), `ELM_TURNSTILE_SECRET`,
   `ELM_ADMIN_TOKEN`.
4. **Приёмка парного режима** (§14.2 шаг 12): два браузера, офлайн, по 20 правок с каждой
   стороны, включить сеть, сверить `stateHash`. До зелёного этого сценария парный режим
   людям не отдавать.

## Что осознанно не сделано в v1

Полный список — §14.2 архитектуры. Коротко: нет аккаунтов, напоминаний, подзадач, тегов,
приоритетов, read-only ссылок, локализации и аналитики. Мосты (почтер, одинэсер) требуют
другой модели доверия и вынесены за пределы первой версии.

Остаточные риски перечислены в §14.3 — их стоит перечитать перед релизом, а не после.
Главные два: потеря ссылки означает потерю данных (так устроено по замыслу), и iOS Safari
чистит хранилище неустановленных сайтов через семь дней.
