# Финансер: интеграция прототипа в кодовую базу

Прототип `Финансер v0.dc.html` больше не живёт параллельно. Логика вынесена в
модули, зеркальные `finanser/src/`, — их можно перенести в репозиторий почти
дословно, поменяв только типы.

| В прототипе | В репозитории | Что делать |
|---|---|---|
| `lib/plane.js` | `src/plane.ts` | новый модуль |
| `lib/merchant.js` | `src/merchant.ts` | новый модуль |
| `lib/rules.js` | `src/rules.ts`, `src/categorize.ts` | без изменений, взято оттуда |

## 1. Универсальная система планов денег — `src/plane.ts`

Вместо флага «исключить переводы» у каждой категории есть план:

- `spend` — деньги ушли наружу, это трата;
- `move` — деньги переехали (перевод, наличные, кредит), это не трата;
- `income` — деньги пришли.

`planeOfTx(category, amount)`: `move` сильнее знака суммы, в остальном знак
решает. Возврат по «Продуктам» — приход, а не отрицательная трата.

Следствия для кода:

- `stats.byCategory` и `stats.totals` считают только `spend`. Добавить
  `byPlane(list): Record<Plane, Totals>` и фильтр `spendOnly(list)`.
- «Движения денег» — отдельная секция под категориями: ушло / пришло / итог,
  по нажатию разворачивается в строки по видам движения.
- Флаг `excludeTransfers` из прототипа удалён: план категории — не настройка.

## 2. Разбор непонятного — `src/merchant.ts`

`merchantKey(description)` выбрасывает из описания организационные формы
(ООО, ИП, LLC), города и технические слова (SBP, TERMINAL, RUS, MOSCOW),
числовые хвосты — остаётся имя получателя. `merchantLabel()` даёт читаемую
подпись: `PYATEROCHKA 1234 MOSCOW RU` → `Pyaterochka`.

Два применения:

1. **Читаемость выписки.** В `TxList` строка показывает `merchantLabel`, полное
   описание уходит в `title`. Сейчас в списке светится сырой мерчант-код.
2. **Разбор «Прочего».** `groupByMerchant(fallbackRows)` собирает одинаковых
   получателей в одну строку с суммой и количеством. Категория ставится
   получателю, а не операции.

Нужен третий слой правок в `store.ts`: помимо `overrides` по `id` —
`merchantOverrides` по ключу получателя, ключ `f.merchant.v1`.
Порядок в `categorize`: `manual` → `merchant` → `rule` → `bank` → `fallback`.
Новое значение `Categorized['source']`: `'merchant'`.

## 3. `MonthChart`: наведение и статистика месяца

- При наведении на столбик над графиком читается строка «месяц · −расход ·
  +приход». Пропс `onHover(month | null)`, состояние держит `app.tsx`.
- Нажатие на месяц открывает статистику месяца: траты, поступления, доля года,
  разбивка по категориям, ссылка «выписка месяца →». Раньше нажатие уводило в
  список операций — теперь список остаётся вторым шагом.
- Подписи месяцев — короткие имена (`янв`), не номера.

Новый компонент `components/MonthStats.tsx`; `MonthChart` остаётся тонким.

## 4. Операции — тише

Операции больше не равноправная вкладка. В картине года — одна строка ссылкой
«вся выписка · N операций →». Вернуться — «← картина года».

## 5. Типографика

- Один шрифт: OCR A Becker RUS-LAT. Basis Grotesque из макета убран.
  В репозитории это `--e-font-sans: var(--e-font-mono)` на корне финансера
  либо `font-family` в `.f-app`/`.f-empty`; `public/fonts/basis-*.woff2`
  можно не грузить.
- Знак рубля не выводим: только значения. `components/Rub.tsx` и `.f-rub`
  удаляются, `Amount` перестаёт его вставлять. Единица понятна из контекста —
  выписка рублёвая.

## Открытое

  выписки их нет. Нужен признак — категория или MCC.
- Порог в «Разборе непонятного» — сейчас 12 верхних получателей. Нужен ли
  «показать ещё», или 12 достаточно.
