# Чертёжер: страница для ИТ-отдела

Сверено с кодом на коммите, указанном внизу. Строки кода — `app.py` этого коммита.

## Что делает

Берёт чертёж DWG или DXF и выдаёт чистый SVG: геометрия стен, окон, дверей, лестниц,
приборов как в исходнике, без текста, размеров, осей, марок и штампа. Работает на
вашем компьютере: браузер → локальная программа → файл SVG.
Номера и площади помещений остаются на плане, но как кривые (контуры глифов шрифта ITC Officina):
в SVG нет текста и нет шрифта. Заливки пола на листах л.2 и л.3 теперь полные (стеклянные стены и
стены без штриховки учтены), заливка вычисляется и приблизительна.
Режим «Проверка» накладывает исходный чертёж на результат, чтобы видеть, что убрано.

## Как устроен (5 строк)

1. `python app.py` запускает веб-сервер из стандартной библиотеки Python на `127.0.0.1:8765`.
2. Страница `ui.html` отдаётся этим же сервером; в браузере выбираете файл.
3. DWG сначала превращает во временный DXF внешняя программа `dwg2dxf` (libredwg); DXF берётся как есть.
4. `dxf2svg.py` (ezdxf + shapely) читает DXF, отбрасывает оформление, пишет SVG.
5. Ответ уходит в ту же вкладку браузера; временный каталог с файлами стирается.

## Что уходит наружу: ничего

- **Только локальный адрес.** `ThreadingHTTPServer(("127.0.0.1", pt), Handler)` (`app.py:324`).
  Сервер не принимает соединений с других машин, в том числе из вашей локальной сети.
- **Чужие вкладки не достучатся.** `_свой()` (`app.py:185–198`) отвечает 403, если имя хоста
  не `127.0.0.1`/`localhost` с нашим портом или если `Origin` чужой. Это закрывает запрос из
  открытой в браузере чужой страницы и подмену имени хоста (DNS rebinding). Проверено:
  чужой `Host` — 403, чужой `Origin` — 403, своя страница работает.
- **В коде нет сетевых библиотек.** Импорты `app.py`: `http.server` (сервер), `urllib.parse`
  (только разбор строк), `subprocess`, `tempfile`, `webbrowser` (открыть `http://127.0.0.1:…`
  в вашем браузере). `dxf2svg.py` и `audit.py` не импортируют ни `socket`, ни `urllib`, ни `requests`.
- **Страница не ходит наружу.** В `ui.html` три запроса — `/styles`, `/convert`, `/decide`,
  все на тот же адрес; шрифт и знак отдаёт тот же сервер. Проверено 06.10.2026 в headless
  Chromium и WebKit на всех демо: страница обращалась только к `127.0.0.1:<порт>` и `blob:`
  (кнопка «Скачать»).
- **Сокеты процесса.** Во время конвертации настоящего DWG (06.10.2026, выборка `lsof` каждые
  0,7 с) у процесса Python и у `dwg2dxf` были только: приём на `127.0.0.1:<порт>` и соединение
  с вашим же браузером по loopback. Других сетевых соединений не замечено; это выборка,
  а не непрерывный перехват.
- **Временные файлы.** Чертёж разбирается в `tempfile.TemporaryDirectory(prefix="чертёжер-")`
  (`app.py:82`); каталог удаляется при выходе из блока, то есть сразу после ответа. Проверено:
  после серии конвертаций `чертёжер-*` во временных папках системы не остаётся. Это обычное
  удаление файлов, не затирание содержимого на диске.
- **Что приложение пишет в папку проекта:** только `layers.json`, когда вы сами отвечаете
  на вопрос о незнакомом слое (`app.py:287`). Демо-чертежи к этому не приводят.

Сеть нужна один раз, при установке: `brew install libredwg` и `pip install -r requirements.txt`
(скачивание с PyPI). После установки чертёжер работает без интернета.

## Зависимости и лицензии

| Компонент | Как используется | Лицензия (по метаданным установленных пакетов, 06.10.2026) |
|---|---|---|
| libredwg `dwg2dxf` 0.14 | отдельная программа, запускается командой `subprocess.run(["dwg2dxf", …])` (`app.py:95`); в репозиторий и в код не вшита, не распространяется | GPL-3.0-or-later (`brew info libredwg`) |
| ezdxf 1.4.2 | библиотека чтения DXF | MIT |
| shapely 2.0.7 | геометрия, заливка пола | BSD-3-Clause |
| numpy 2.0.2 | зависимость shapely | BSD |
| fonttools 4.60.2, pyparsing 3.3.3 | зависимости ezdxf | MIT |
| typing_extensions 4.16.0 | зависимость ezdxf | PSF-2.0 |
| ITC Officina Sans Book | шрифт цифр помещений; коммерческий файл `.otf` лежит на машине пользователя, в репозиторий не входит; в SVG попадают только очертания знаков (кривые), сам шрифт не встраивается | коммерческая, лицензию на такое использование не проверяли |
| Python 3.9.6 | системный `/usr/bin/python3` macOS | PSF |

GPL относится к libredwg, который вызывается как отдельный процесс на машине пользователя
и не входит в код элементара. Решение владельца по зависимостям — О-17, вариант 1 (06.10.2026):
Python, ezdxf и shapely — зависимости разового инструмента в `scripts/`, в сборку корпусов
не входят; libredwg не вшивается и не распространяется. Перед тем как чертёжер выйдет из
`scripts/` в продукт, лицензии проверяются заново. Юридической оценки здесь нет — это
перечень по метаданным.

Версии зафиксированы в `requirements.txt`. Код самих библиотек и `dwg2dxf` нами не аудировался.

## Ограничения

- Бета (`Beta v0.1` на странице). Результат нужно смотреть глазами, для этого есть режим «Проверка».
- У сервера нет входа по паролю: любой процесс на этом же компьютере под любым пользователем
  может обратиться к `127.0.0.1:8765`. Если на машине работают несколько человек, это важно.
- Заливка пола вычисляется, а не берётся из чертежа, и приблизительна (см. `README.md`).
- Читается пространство модели; чертёж, у которого всё лежит на листах (paper space),
  отклоняется с объяснением.
- Файл до 200 МБ; `dwg2dxf` — до 10 минут, разбор — до 30. Файл в 30 МБ с сотнями тысяч объектов
  (настоящий DWG из ArchiCAD) дошёл до остановки на незнакомых слоях за 147 секунд; на настоящих
  DWG 0,7–1,9 МБ полная конвертация занимает 2–4 секунды.
- Незнакомые слои останавливают сборку и требуют ответа; ответ запоминается в `layers.json`.
- Проверено на macOS (Apple Silicon), Python 3.9.6. На Windows и Linux не пробовалось.

## Что дальше

Решение владельца по месту чертёжера: остаться инструментом в `scripts/` или стать корпусом
(тогда — отдельная проверка GPL); профили раскладки у разных проектировщиков; выбор чертежа
на листе в интерфейсе; точный контур пола вместо вычисленного.
