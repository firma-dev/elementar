# чертёжер

DWG или DXF → чистый SVG со стилизацией. Геометрия берётся из чертежа как есть,
ничего не достраивается и не подгоняется. Убирается оформление: текст, размеры, оси,
марки, отметки, штамп, облака изменений, выноски узлов.

Инструмент разработчика, не корпус. Зависимости живут в локальном `.venv` и в проект
не попадают — как у `scripts/build-fonts.py`.

> Решения по зависимостям (libredwg через Homebrew, ezdxf, shapely) в `DECISIONS.md`
> пока нет. По `CLAUDE.md` зависимость не добавляется без решения архитектора —
> запись нужна до того, как этим начнут пользоваться другие.

## Разовая подготовка

    brew install libredwg
    python3 -m venv .venv && .venv/bin/pip install -r requirements.txt

Версии в `requirements.txt` зафиксированы намеренно: заливка пола строится
буферизацией shapely, а замкнутость контуров берётся у путей ezdxf — смена версии
любого из двух двигает результат молча. Версия `dwg2dxf` не ставится, а сверяется
при старте приложения; расхождение — предупреждение.

`libredwg` под GPL-3.0 — это важно, если чертёжер когда-нибудь встроят в корпус.

## Приложение: три кнопки

    .venv/bin/python app.py

Открывает http://127.0.0.1:8765. Загрузить DWG или DXF, выбрать стиль, скачать SVG.
Кадрировать вручную не нужно: лист считается по конструктиву, а оформление рядом с
планом отсеивается само.

Если на листе несколько чертежей — план и узел, план и фрагмент, два этажа рядом —
появляется шаг «Чертёж на листе» с их габаритами. По умолчанию берётся самый крупный.
Отсеять их автоматом нельзя: это не оформление, а настоящая геометрия со стенами,
поэтому выбирает человек.

Сервер слушает только `127.0.0.1`, чертёж разбирается во временном каталоге, который
стирается сразу после ответа. Наружу ничего не уходит — это требование `CLAUDE.md`
про файлы пользователя.

Интерфейс собран в языке прототипа «элементар ос» — elementaros.ru/prototip2.
Приёмы сняты с него: всё моноширинным капсом OCR, ноль радиусов, чёрные тени со
смещением, нумерованные метки разделов чёрной плашкой, жёлтая плашка для главного,
цветная полоса сверху у карточек. Шрифт OCR отдаётся сервером из репозитория, знак —
из `packages/brand`.

**Палитра здесь своя, прототипа, а не семантический слой Элементара.** У прототипа
вивидный жёлтый, чистый белый и нейтральный чёрный, которых в `tokens.css` нет: там
тёплая бумага. Сводить одно к другому — работа `designer`, за ним и токены, и решение.
Пока чертёжер живёт отдельным инструментом, он говорит на языке прототипа как есть.

Из этого следует и другое: тёмной темы у прототипа нет, значит нет и здесь.

Стили лежат в `styles/`. Новый стиль — это новый файл рядом с `бадаевский.json`,
он появится в интерфейсе сам.

## Прогон вручную

    .venv/bin/python audit.py plan.dxf
    dwg2dxf -o plan.dxf исходник.dwg
    .venv/bin/python dxf2svg.py plan.dxf out/план.svg --crop X0 Y0 X1 Y1

`audit.py` печатает слои, их габариты, решение по каждому из `layers.json` и готовую
строку `--crop` по всему содержимому. Сузив её, отсекают то, что лежит рядом с планом
на том же листе: таблицы, узлы, детали.

`--report` печатает сверку «в модели → нарисовано» по каждому слою.
`--fragments` печатает список чертежей на листе в JSON, `--fragment N` выбирает нужный,
`--fragment all` берёт всё. Порог, по которому лист делится, задаётся `--gap` (5 м).

## Несколько чертежей на одном листе

Конструктив разбивается на острова по пустоте между ними: объекты раскладываются в
сетку с ячейкой `--gap`, связные области ячеек — это отдельные чертежи. Сетка нужна,
чтобы не сравнивать каждый объект с каждым: их пятнадцать тысяч.

Проверено на двух листах одного комплекта: на К2_2 находится один чертёж, на К2_1 —
два, план 35×55 м и фрагмент 7×7 м. Без разбиения лист К2_1 выходил 651 мм при плане
на 358 мм: половина листа была пустой, а в углу висел фрагмент.

## Что где

| Файл | Что |
|---|---|
| `app.py` | локальный сервер и три кнопки |
| `ui.html` | интерфейс на токенах Элементара |
| `check.py` | гейт: синтетика плюс эталоны |
| `эталоны.json` | ожидаемые числа по настоящим чертежам |
| `requirements.txt` | пины версий |
| `audit.py` | отчёт по слоям, габаритам и типам объектов |
| `dxf2svg.py` | разбор и рендер |
| `layers.json` | решение по каждому слою, с причиной |
| `styles/*.json` | стили: цвета, толщины, заливки |

Геометрия и вид разделены: чтобы поменять подачу, правится только `style.json`.

## Как читать layers.json

`drop` — слои оформления, с причиной у каждого. `class` — во что превращается слой:
`wall`, `slab`, `window`, `door`, `stair`, `fixture`, `generic`.

Слой, которого нет ни в `drop`, ни в `class`, в SVG **не попадает**, и скрипт называет
его в конце прогона. Класс, которого нет в `style.json`, останавливает прогон до
разбора файла: без `fill` и `stroke` группа зальётся чёрным поверх всего чертежа.

Кроме слоёв, всегда выбрасываются типы MTEXT, TEXT, ATTRIB, ATTDEF, DIMENSION, LEADER,
MULTILEADER, TOLERANCE — подписи попадаются и в конструктивных слоях.

`bbox_classes` — по чему считается габарит здания. Прочая графика в расчёт не входит,
иначе лист задаёт случайная выноска. Всё, что целиком лежит вне габарита здания,
отбрасывается как оформление рядом с планом и попадает в отчёт о потерях.

## Гейт

    .venv/bin/python check.py

Падение = чертежи собирать нельзя. Две части.

**Синтетические чертежи** порождаются кодом и работают у любого, кто склонировал
репозиторий. Каждая проверка закрывает найденную ошибку, а не абстрактную
правильность: эллипс-дуга не замыкается хордой, остров в штриховке остаётся дыркой,
незамкнутый контур не заливается, лист делится на чертежи, слой без решения
останавливает прогон, заливка пола на комнате с проёмом сходится с её габаритом.

**Настоящие чертежи** — пути в `эталоны-пути.json` рядом со скриптом (в репозиторий
не попадает, чертежи под NDA), переопределяется переменной `CHERTEZHER_ETALONY`.
Ожидаемые числа лежат в `эталоны.json` и коммитятся: это агрегаты, геометрию объекта
они не раскрывают. Нет файла с путями — гейт честно скажет, что проверил только
синтетику.

Каждая проверка гейта проверена на способность краснеть: восемь поломок вносились
нарочно, все восемь пойманы. Зелёный гейт, который не умеет краснеть, бесполезен.

## Отказ вместо тихой потери

Слой без решения **останавливает прогон**: SVG не пишется, код возврата 1, слой назван.
Приложение в этом случае возвращает 422 и не показывает кнопку скачивания. Раньше
такой слой давал предупреждение строкой в отчёте — именно так молча пропали
«Стены перегородки», 911 объектов на весь дом.

Для разведки есть `--allow-unknown`: прогон пройдёт, но нерешённый слой в SVG не попадёт.

## Разбор незнакомого слоя

Приложение не просто отказывает, а спрашивает. На каждый нерешённый слой рисуется
картинка: сам слой поверх бледного контура стен, кадр — по основному чертежу. Под ней
три кнопки:

| кнопка | во что превращается |
|---|---|
| Стена | класс `wall`, поше |
| Второстепенное | класс `generic`, тонкая линия |
| Оформление | список `drop`, в SVG не попадёт |

Ответ пишется в `layers.json` с причиной. Когда разобраны все слои, чертёж собирается
сам. Это ровно то, что раньше приходилось делать руками, отрисовывая слой через
matplotlib и вписывая имя в конфиг.

Из консоли то же самое: `dxf2svg.py … --preview-unknown КАТАЛОГ` кладёт по картинке
на слой и печатает JSON с путями.

Перед записью файл проверяется: вся геометрия внутри `viewBox`, у каждой группы есть
`fill` и `stroke`, нет `<text>`, `<tspan>`, `font`. Не прошло — отказ, файл не пишется.

## Баланс объектов

Каждый объект после разворота вставок попадает ровно в одну корзину: нарисован,
выброшен по слою, выброшен по типу, слой без решения, нет геометрии, ошибка разбора,
отсечён кадрированием, вне габарита, другой чертёж на листе. Сумма сверяется с числом
объектов на входе, и расхождение — это ошибка самой программы: файл не записывается.

Баланс печатается всегда, а не только при потерях.

## Потери

Скрипт печатает раздел «ПОТЕРИ» с разбивкой по слоям: что не дало геометрии, что
отсечено кадрированием, где сломался разбор, что лежало вне габарита. Пустой раздел
означает, что не потеряно ничего. Числа в сверке `--report` — это то, что **нарисовано**,
а не то, что решено оставить.

## Заливка пола

В чертеже её нет: слой «Перекрытие» содержит одну штриховку на три метра. Поэтому
пятно застройки считается по телам стен, перечисленным в `footprint_layers`.

Тела стен в выгрузке Revit — отдельные штриховки с зазорами, а в проёмах — настоящие
разрывы. Полигоны раздуваются на `--bridge` (1500 мм), объединяются, из крупнейшей
компоненты берётся внешний контур, мостик снимается обратно. `--opening` (700 мм)
срезает тонкие языки, результат подрезается по габариту.

**Это единственное место, где геометрия вычисляется, а не берётся из чертежа, и она
приблизительна.** Замерено на этом плане: 34 % периметра заливки отстоит от тел
наружных стен дальше 300 мм, худший отрыв 1190 мм, 11,5 % длины линий наружных стен
осталось вне заливки. Мостик даёт не скругление в углах, а диагональные срезы поперёк
здания. На листе 1:100 метр промаха — это 10 мм на бумаге, и он виден.

Ограничения, о которых надо знать:

- заливается только крупнейшая связная компонента стен; если корпусов два, второй
  останется без пола — скрипт об этом предупредит в отчёте;
- берётся только внешний контур: здание с внутренним двором или атриумом получит пол
  и там. Флаг `--keep-holes` сохраняет дыры, но на обычном плане он вырежет комнаты,
  потому что отличить двор от большого зала по геометрии нечем;
- колонны в `footprint_layers` не входят: стоящие за контуром здания, они притянулись
  бы мостиком и дали шипы наружу.

Отключается флагом `--no-floor`. Слой вынесен отдельной группой `c-floor` — если
появится точный контур, он заменяется одной группой.

## Заливки и незамкнутые контуры

Заливка кладётся только на замкнутые контуры. Открытый путь SVG при заливке замыкает
хордой: из дуги унитаза получилась бы белая линза поверх пола. Поэтому классы с
заливкой делятся на две группы: `c-fixture` — замкнутое, `c-fixture-open` — открытое,
только обводкой.

Следствие, которое надо знать: в этом чертеже сантехника нарисована отдельными дугами
и отрезками, замкнутых контуров среди 1994 всего 16. Белыми силуэтами, как в
референсе, приборы не станут — в исходнике нет замкнутых контуров, из которых их можно
было бы собрать.

## Почему вид задан атрибутами, а не CSS

Illustrator не понимает `var()`. Если вид задать переменными в блоке `<style>`, он
откроет файл с пустыми заливками — векторы на месте, картинки нет. Поэтому цвета и
толщины пишутся презентационными атрибутами на группах: их понимают и Illustrator, и
InDesign, и браузер.

Имена токенов Элементара в `style.json` намеренно не упоминаются. Они не совпадают с
этой палитрой, а `DESIGN.md` §3.1 запрещает примитивы вроде `--e-paper-800` в корпусах.
Если чертёж пойдёт в интерфейс, семантические токены под него заводит `designer`.

## Размер листа

Координаты переносятся в ноль, `width` и `height` задаются в миллиметрах по масштабу
(`--scale`, по умолчанию 1:100). Без физического размера Illustrator берёт свой артборд
по умолчанию и кладёт чертёж по сырым координатам, далеко за пределами листа.

## Проверка результата

- раздел «ПОТЕРИ» пуст или каждая строка объяснима;
- сверка `--report` по конструктивным слоям сходится;
- единица SVG равна миллиметру чертежа: длины отрезков совпадают с DXF;
- вся геометрия внутри `viewBox`, начало координат в нуле;
- в выдаче нет `<text>`, `<tspan>`, `font`;
- у каждой группы есть свои `fill` и `stroke` — иначе Illustrator покажет пустой лист.

Габарит SVG **не равен** габариту DXF: `--margin` добавляет по 300 мм с каждой стороны,
и лист считается по тому, что осталось после отсева.

## Чего здесь нет

Профилей раскладки: `layers.json` один на всех. Слой со знакомым именем, но другим
смыслом у другого проектировщика классифицируется неверно и молча — это единственная
оставшаяся дыра, через которую можно потерять геометрию.

Точной заливки пола: она по-прежнему вычисляется буферизацией, со всеми замеренными
промахами выше.
